## 2026-10-14 早报

- **一篇把 agent loop 拆成三层来调试的文章**
  Micheal Lanham 主张别把 agent 当单一循环调试，拆成 L1 工具调用循环 / L2 任务循环 / L3 编排循环。L1 的收口正是你反复卡壳的点：模型不再吐 tool_call、改输出给用户的纯文本消息即结束，没有外部分数。跟你的关系：你正在写的架构说明可以借用这层划分，把 Divana 的「模型自主判断停止」明确钉在 L1 层。
  [来源](https://medium.com/@Micheal-Lanham/stop-debugging-your-agent-as-one-loop-its-three-d10013fa3a7e)

- **9 月一批长程 agent 上下文压缩论文**
  Awesome-Efficient-Agents 列表收录了 2026-09 的 CliffCompaction（编码 agent 的成本高效压缩）、"When Can Agents Forget Their Reasoning?"（ICLR 长程上下文压缩）等。跟你的关系：你下一步要写「上下文裁剪」的架构说明，这几篇能帮你区分压缩 / 遗忘 / 结构化记忆几种策略，不用自己发明名词。
  [来源](https://github.com/yxf203/Awesome-Efficient-Agents)

- **HAL 进了 ICLR 2026，公开了 agent 评测的成本账**
  普林斯顿的 Holistic Agent Leaderboard 用统一 harness 跑 9 模型 × 9 benchmark 共 21,730 次 rollout，花约 4 万美元，公开 25 亿 token 日志并集中追踪每次成本。跟你的关系：你要建 20 条评测集、算端到端成功率和单次 token 成本，「统一 scaffold + 集中计成本」这套做法可以小规模照抄。
  [来源](https://o-mega.ai/articles/the-best-ai-agent-evals-and-benchmarks-full-2025-guide)

- **上下文裁剪实操：observation masking**
  Atlan 的 2026 指南第 3 步讲 observation masking：把较旧的工具返回替换成紧凑占位符，每个工具只保留最近 M 条完整输出，且无需再调一次 LLM。跟你的关系：这一步把「Observation=工具返回」和「裁剪」绑在一起，正好同时巩固你两点——Observation 是工具结果、不是画像注入；裁剪发生在 observation 层而非画像层。
  [来源](https://atlan.com/know/ai-agent/ai-agent-context/how-to-implement-context-pruning-ai-agents)

### 今天可以动手的一件事
