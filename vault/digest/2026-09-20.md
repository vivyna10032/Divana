## 2026-09-20 早报

- **Turing Post 对比了 7 种 agent 记忆架构，核心是把多 agent 记忆当作"计算机架构"来设计**
  文中介绍的论文将多 agent LLM 系统记忆类比为计算机体系结构：共享 vs 分布式记忆、三层记忆层级（I/O / cache / memory）、agent 间 cache 共享协议、记忆一致性等。跟你的关系：Divana 的"三层记忆 + 多 agent 回顾"正好撞上这些概念，读它能帮你在写架构说明时把现有设计对应到"cache/主存"这层抽象，命名和分层会更清楚。
  [来源](https://www.turingpost.com/p/agenticmemory)

- **Atlan 出了一份 context pruning（上下文裁剪）的可落地方法**
  给出可执行的裁剪管线：给上下文条目打 intent 标签、observation masking、graduated pipeline，工具用 `tiktoken` + `sentence-transformers`。跟你的关系：你下一步要写"上下文裁剪"的架构说明，这篇提供了打分/裁剪的步骤拆解，可以对照 Divana 现有实现看缺了哪一层。
  [来源](https://atlan.com/know/ai-agent/ai-agent-context/how-to-implement-context-pruning-ai-agents)

- **Augment Code 的《AI Agent Loop Token Costs》讲怎么约束 agent loop 的上下文成本**
  围绕 agent loop 中 token 膨胀的问题，给出约束上下文的具体手段。跟你的关系：你马上要算"端到端成功率 + 单次 token 成本"，这篇能帮你设计成本测量口径（哪些轮次、哪些工具调用该计入），避免算出来的 token 成本失真。
  [来源](https://www.augmentcode.com/guides/ai-agent-loop-token-cost-context-constraints)

- **Spheron 分析 agent 推理成本：agent 工作负载消耗 5–30 倍 token**
  指出 agentic 负载本身有 5–30 倍的 token 乘数，叠加 Claude Sonnet 5 自 9 月起涨到 $3/M 输入、$15/M 输出。跟你的关系：算 Divana 单次 token 成本时，这个 5–30 倍乘数是很好的基准参考，能帮你判断自己的裁剪是否真的在省钱。
  [来源](https://www.spheron.network/blog/agentic-ai-inference-cost-2026)
