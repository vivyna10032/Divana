## 2026-10-13 早报

- **Hello-Agents 框架更新到 V1.0.0，并放出新学习路线**
  Datawhale 的《从零开始构建智能体》框架已升到 V1.0.0，新增轻量化工具、兼容学习版，2026 年 5 月更新了学习路线，配套代码在 `code/` 文件夹可直接跑。跟你的关系：你正用它系统补 agent 原理，重点读它的记忆与 loop 章节，对照 Divana 看设计取舍。
  [来源](https://github.com/datawhalechina/hello-agents)

- **Mem0 架构论文：记忆按三级作用域划分（user / session / agent）**
  论文把记忆流程拆成提取 → 冲突检测 → 图更新两阶段，作用域分用户/会话/agent 三层，后端用向量检索 + 知识图谱混合，宣称比全量上下文省约 90% token。跟你的关系：Divana 是三层记忆，可以拿 Mem0 的作用域划分对照，检查你每层存什么、谁负责读写和更新。
  [来源](https://zylos.ai/research/2026-04-05-ai-agent-memory-architectures-persistent-knowledge)

- **Agent 的单次 token 成本主要由架构决定，不是模型单价**
  同一多文档评测任务，固定上下文的单次结构化 pass 每轮约 $1.34，而"携带全部历史重放"的 agent 要 $4.64（重放了 3.6 倍输入 token）；多投票追精度会推到 $10–15/轮。跟你的关系：你正算单次 token 成本，这条提醒你要盯"输入重放量"，而不是只看输出 token。
  [来源](https://mightybot.ai/blog/token-economics-of-ai-agents-2026)

- **2026 评测惯例：能力指标必须和成本、延迟一起报**
  只看 90% 成功率、不提每任务 10 万 token / 30 秒，是不合格的评测。当前做法是能力 + 成本 + 延迟并列，必要时画 Pareto 前沿。跟你的关系：你建 20 条评测集时别只记成功率，每条把 token 数一并记录，才有"成本"可算。
  [来源](https://toloka.ai/blog/ai-agent-evaluation-benchmarks-frameworks)

### 今天可以动手的一件事

拿评测集里的同一条任务，用两种配置各跑一遍：A) 每轮只带裁剪后的必要上下文；B) 携带全部历史重放。两边都记录 input/output token，算出单次成本差。这一步直接练到你"端到端成功率 + 单次 token 成本"的下一步，也能量化 Divana 的上下文裁剪到底省了多少。
