# Agent loop 的循环与停止条件

## 一句话结论

Agent loop 是「模型决策 → 调工具 → 观察结果 → 再决策」的循环。它的收口（停止条件）是：模型判断当前信息够不够直接回答，够就输出**不带 tool_call 的纯文本答案**——这个输出动作本身就是停止信号。

## 完整 loop 结构

1. 组装上下文：人格 + 画像 + 记忆 + 用户输入
2. 模型产出决策：要么调工具，要么直接回答
3. 若调工具 → 执行 → 拿到结果（Observation）→ 结果追加回上下文
4. 回到第 2 步，让模型重新决策
5. 直到某一次模型输出不带 tool_call 的纯文本 → 循环结束

## 停止条件的三个关键点

1. **判断者**：模型自己，不是代码里写死的「循环 N 次就停」。
2. **判断依据**：模型推断「当前 Observation 够不够直接回答」，这是对信息充分性的内部推断——不是外部喂进来的「解决度分数」。
3. **停止形式**：没有单独的「问它解决了没」这一步。模型每轮要么输出 tool_call、要么输出纯文本；输出纯文本（无 tool_call）这个动作就等于宣布停止。

## 常见误区

- 把 **Observation 和画像/记忆注入**混为一谈：画像是循环开始前就注入的背景板，Observation 特指工具返回的结果。
- 以为有个外部「解决程度」分数喂给模型——没有，是模型的内部推断。
- 以为循环里有人「问模型解决没解决」——没有，停止是模型输出形式的自然结果。

## 在 Divana 代码里怎么找这个收口

找「检查模型这轮输出里有没有 tool_call」的逻辑：

- 有 → 执行工具、结果塞回上下文、继续循环
- 没有 → 当作最终答案返回给用户

那个「没有 tool_call」的分支，就是循环的终点。
