# Agent 的工具与记忆：一次失败到成功的验证

# Agent 的工具与记忆

> 以下内容来自 Divana 项目的一次实测（2025-10 前后），可脱离原对话独立阅读。

## 核心结论

一个 agent 由「身份 + 工具 + 记忆 + 循环」构成。本次实测走通了工具从失败到成功的完整路径。

## 记忆分层

- **短期记忆 = 上下文窗口（context window）**：只装当前会话内容，会话结束（关闭进程）就清空，不会自动落盘。
- **长期记忆 = 画像 / 笔记文件**：跨会话保留，存的是**提炼后的结论**，不是逐字流水账。
- 因此重启后 agent 只记得写进长期记忆的部分，逐字对话会丢失。

## 工具：声明 vs 真实可用

- 工具在 agent 里只是「声明存在」——有名字、描述、参数 schema，但真正执行时才可能失败（缺 key、超时、返回格式不对等）。
- 靠谱的 agent 应该**如实转达失败**，而不是假装成功或瞎编结果。

## 实测路径

1. 调用联网搜索工具 → 返回「还没有配置搜索 key」（工具声明了但不可用）。
2. agent 如实转达失败，并提示在 `.env` 里填 `DIVANA_SEARCH_API_KEY`。
3. 修复配置后重启进程 → 再次调用 → 成功，返回结果并附出处链接。

## 关键细节

- `.env` 文件一般在**进程启动时**读入内存，改完必须**重启进程**（不只是重开命令行窗口）才会生效。
- 排查「配置没生效」时，最直接的办法是去代码里搜对应的 key 名（如 `DIVANA_SEARCH_API_KEY`），看它到底从哪读、何时读。
