# Divana练手：agent核心机制

## 这次聊了什么

用户想搞懂 agent 怎么运作，拿 Divana 项目当练手对象。过程中亲手验证了联网搜索 key 从失败到成功的过程，理解了记忆分层的实际含义，还让 Divana 读了自己的公开仓库并提炼出 5 个可迁移的 agent 工程要点，最后存成笔记。

## 关键结论

### Agent 的基本骨架

一个 agent 由四部分组成：**身份 + 工具 + 记忆 + 循环**。Divana 能读到自己的“说明书”（system prompt、工具定义、记忆文件、思考机制），但看不到“发动机”（背后模型、外部驱动循环）。这说明 agent 的可见层和底层是分离的。

### 记忆分层

- **短期记忆 = 上下文窗口**：当前对话的逐字内容，会话结束就清空。
- **长期记忆 = 画像文件**：跨会话保留，但存的是提炼后的结论，不是原话。
- 重启后能记得画像里写过的内容（比如用户的学习目标），但不会记得逐字对话。
- 判断“什么进长期记忆”的标准：这个信息以后还用不用得上。随口一提不记。
- 更细的分层标准：**要不要常驻眼前**。画像必须小，因为每轮都要拼进 system prompt；笔记不占窗口，靠工具按需取；会话存档只带最近 N 条（`HISTORY_LIMIT`）。

### 工具：声明与真实可用是两回事

- 工具是“给模型的说明书”，模型只能看到函数名、docstring、参数 schema，看不到函数体。改工具说明 = 改行为。
- 工具“声明存在”不等于“真的能用”。用户亲历：`search_web` 声明了，但第一次调用返回“没有配置搜索 key”。
- 修好后重启时，关键坑是**.env 必须重启运行 Divana 的进程**才生效，只重开窗口不够。
- 工具失败时要如实转达，不能瞎编结果。这条是 agent 行为准则。

### 多 agent 的本质

多 agent 不是炫技，判断标准是：**素材在主 agent 眼前，就不需要第二个 agent；主 agent 看不到，才另起一个**。例如“回顾对话”单独用一个总结者 agent，因为主 agent 的上下文只有最近 40 条，看不到完整历史。本质是不同任务用不同上下文 + 不同指令。

### 工程化实践

- **把链路拆成可单独验证的段**：`/search` 命令绕过模型单独测搜索通不通，和“模型会不会调它”分开验。启动信息显示配置来源、画像路径、搜索状态，方便定位“填了 key 却没生效”。
- **成本刹车**：`HISTORY_LIMIT` 限制带进模型的条数。
- **安全边界**：只允许 `http/https`，挡掉 `file://`，防 prompt injection。

### 外部项目对比

- **smolagents**：核心 agent loop 挤在一个 `agents.py` 里（约 1000 行），适合直接读。
- **Hello-Agents**（Datawhale）：中文教程，第四章手把手实现 ReAct、Plan-and-Solve、Reflection，第七章从 0 搭框架，第八章讲记忆与检索。
- **ai-engineering-from-scratch**：Phase 14 的“The Agent Loop”正对口。

## 他的理解进度

- **原来不懂、现在懂了**：重启后 agent 不会记住逐字对话，只记得画像里的提炼结论；工具声明了不代表能用；配置改了必须重启进程。
- **只是接受结论、还没验证**：从 Divana README 提炼的 5 个工程要点，依据的是 README 里的目录注释，不是实际读代码验证过的。Divana 自己也承认没读到具体源码。
- **亲手做过**：填 `.env`、重启、验证联网搜索成功（Python 最新稳定版 3.14，2025-10-07 发布）。

## 还没解决的

- 用户想让 Divana 读具体代码文件（`tools.py`、`agent.py`、`profile.py`），但 `read_github_repo` 工具只返回元信息和 README，实际源码没读到。需要贴文件内容或用 raw 链接。
- 第一次填 key 后重启仍失败，Divana 列了排查项（变量名、文件路径、是否真的重启进程、去代码搜），但中间具体是哪个环节导致失败，记录里没有明确后续排查过程。
- Hello-Agents 第四章的具体内容说要“带过一遍 ReAct”，用户说暂时不用了，所以还没学。

## 下一步建议

1. 把 `divana/tools.py` 和 `divana/profile.py` 的文件内容直接贴给 Divana，或者给 raw 链接（`https://raw.githubusercontent.com/vivyna10032/Divana/main/divana/tools.py`），逐条验证那 5 个工程要点是否真的在代码里落地。
2. 从 Hello-Agents 第四章的 ReAct 实现开始，对照 Divana 里已经走通的“工具失败→转达→修复→成功”循环，理解 ReAct 是怎么从零写的。
